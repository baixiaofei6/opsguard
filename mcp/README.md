# OpsGuard · MCP 薄适配层（mcp/）

> 本期状态：**占位**。本目录保住目录结构与接口定义，不实现任何可运行 server，不引入任何 MCP SDK 依赖，不阻塞 CLI 主线。

## 为什么是占位

按 TASK.md 宪法第 2 条与 §2：MCP 与 CLI 同期交付，但放在同仓库独立 `mcp/` 目录，CI 与测试不阻塞 CLI 主线；本期「占位保底（保住目录与接口定义）、薄层实现视余力」。砍掉整个目录也不伤 CLI 内核。

本期把有限时间投在 P0（脱敏层、AST 安全门、确认门、备份回滚哈希、黄金测试、3 分钟闭环），MCP 按 P2 处理，因此只留占位。占位不等于「永久不实现」——它是为后续薄层实现保留的接缝。

## 职责边界

- 只规划暴露**只读诊断**接口：接收只读诊断请求，返回诊断建议文本。
- **MCP 不做修改命令执行**：不提供任何写操作、执行类工具，也不持有备份/回滚执行入口。
- 执行必须回到 CLI，由人显式确认后走既有确认门与执行器；MCP 层不得绕过。
- 建议文本若来自云端链路，必须先过 `c1/` 脱敏层（出网唯一出口）；无 Key 时走离线规则模式，不包装成离线 AI。
- 本目录不参与 CLI 主线的测试与 CI；新增的 MCP 测试即使是未来实现，也不得让主线红灯。

## 接口草案

见 `mcp/interface-draft.md`（职责边界级，不到字段级）。

## 明确不做

- 不写可运行 server、不引入 MCP SDK 或任何第三方包（零依赖红线）。
- 不提供「自动批准」「跳过确认」「无超时自动执行」入口。
- 不实现本地模型插件、通用 RAG、Prompt 编排（非目标，见 TASK §2）。
