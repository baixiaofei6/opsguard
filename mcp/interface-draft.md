# OpsGuard · MCP 接口草案（职责边界级）

> 只描述职责与语义边界，不列字段、不列函数签名、不写可运行 server，不引入任何 MCP SDK 依赖。后续若要实现薄层，再按此草案细化。

## 规划暴露的能力（只读）

| 能力 | 输入语义 | 输出语义 | 判定/约束 |
|---|---|---|---|
| 只读诊断 | 一段报错文本或只读采集请求 | 诊断结论 + 风险排序 + 建议动作文本 | 复用 CLI 的 `c2/diagnose.py` 诊断引擎；本层不做判定 |
| 建议命令展示 | 诊断结论 | 候选命令文本 + 一句人话 + diff 素材 | 复用 `c2/generate.py`；候选命令必须经过 `c2/AstGuard.psm1` 三态判定后才展示 |
| 判定结果查询 | 候选命令文本 | 三态（allow_readonly / require_confirm / deny）+ 理由 + 命中节点 | 复用 AST 安全门，本层不自行判定、不放宽结果 |

## 明确不暴露的能力

- 不暴露任何执行工具（无 run / exec / apply / write）。
- 不暴露备份、回滚、确认门放行、冻结解除入口——这些只在 CLI 人工确认路径上。
- 不暴露「跳过确认」「自动批准」参数。

## 与内核的边界

- 数据源与判定全部委托 CLI 内核已有模块（诊断引擎、命令生成、AST 校验器、脱敏层）；MCP 层只做只读透传与建议返回，不新增业务判断。
- 任何建议要出网（有 Key 云端解读）必须先过脱敏层；映射表只留本地。
- 执行语义：MCP 返回的永远是「建议」，人要执行时回到 CLI，走 `y/N` 默认 N 的确认门与备份回滚流水线。
- 失败语义：解析失败、白名单外、无法判定一律 deny 并给出理由（fail-closed），不静默放行。

## 交付约束

- 本目录的测试（若未来新增）不阻塞 CLI 主线 CI；主线验收不得依赖本目录。
- 零第三方依赖；不引入 MCP SDK 包；PowerShell 5.1 为唯一运行时基准。
